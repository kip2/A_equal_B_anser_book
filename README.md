# A=B Answer Book

プログラミングパズルゲーム [A=B](https://store.steampowered.com/app/1720850/AB/)（Steam）の、自分の解答集とテクニック集です。

> [!WARNING]
> ネタバレ注意：全ステージの解答と解説を含みます。

🔗 サイト：<https://kip2.github.io/A_equal_B_anser_book/>

## サイトの見方

### ページ構成

```text
トップ
├── チャプター一覧
│   └── チャプター N ── ステージ一覧 / このチャプターのテクニック / このチャプターの文法
│       └── ステージ N-M ── 問題・解答・考え方 / 使ったテクニック / 文法
├── テクニック総覧
│   └── 各テクニック ── 解説 / 使ったステージ / 関連する文法
└── 文法総覧
    └── チャプター N の文法 ── 解説 / このチャプターのステージ / 関連テクニック
```

| ページ | 内容 |
| --- | --- |
| トップ | 全チャプター・テクニック・文法の目次と、クリアしたステージ数 |
| チャプター | そのチャプターのステージ一覧、使えるようになったテクニック、追加された文法 |
| ステージ | 問題の要約、解答コード、考え方。下に使ったテクニックと文法へのリンク |
| テクニック総覧 | 全テクニックを「使えるようになるチャプター」ごとに一覧 |
| 文法総覧 | チャプターごとに追加される文法を一覧 |

ステージ・テクニック・文法はお互いにリンクしているので、どこからでも関連するページへ移動できます。

### 操作

- `[+]` / `[-]` の付いた見出しは、クリックすると開閉します。
- 総覧ページなどにある `[すべて開く]` / `[すべて閉じる]` で、ページ内の見出しをまとめて開閉できます。
- 解答コードの右上のコピーアイコン（重なった2枚の紙）で、コードをクリップボードにコピーできます。
- ページ上部のパンくず（`トップ / チャプター / チャプター1 / 1-1`）から上の階層に戻れます。
- ステージ・チャプター・文法のページ下部の `<<` / `>>` で、前後のページに移動できます。

### 表記

| 表記 | 意味 |
| --- | --- |
| `3行 / 12ステップ` | 解答の行数とステップ数。`-` は未記録 |
| `クリア` / `挑戦中` / `未着手` | ステージの状態 |
| `チャプターN〜`（テクニック） | そのテクニックがチャプター N の文法から使えること |

## 記事の追加

記事は `content/` に Markdown で書きます。手順・書式・雛形は [docs/writing.md](docs/writing.md) にまとめています。

- Claude Code では `/add-article` で追加を頼めます。
- ページ間のリンクや一覧・進捗は frontmatter から自動で生成されます。
- `main` に push すると、テストが通ったあと自動で公開されます。

ローカルで表示を確認するには:

```sh
go run ./builder -serve      # http://localhost:8080/
```

## テスト

```sh
go test ./...                      # すべて
go test -skip '^TestBuild' ./...   # ユニットテストのみ
go test -run '^TestBuild' ./...    # 結合テストのみ
```

### ユニットテスト（[builder/content_test.go](builder/content_test.go)）

| テスト | 確認していること |
| --- | --- |
| `TestSplitFrontMatter` | frontmatter と本文の切り分け。frontmatter なし・CRLF・BOM 付き・空・閉じていない場合も正しく扱えるか |
| `TestIntText` / `TestStatusLabel` / `TestDisplayTitle` | 行数の `-` 表示、状態の表示名、チャプター・文法のタイトル表記 |
| `TestLoadSite` | コンテンツの読み込みと関連付け。チャプター・ステージの並び順、チャプターをまたぐ前後リンク、`title` / `status` の省略時の値、ステージ ⇔ テクニック ⇔ 文法の相互リンク、使ったテクニックの重複除去 |
| `TestLoadSiteEmpty` | `content/` が空でもエラーにならないか |
| `TestLoadSiteErrors` | 書き間違いをエラーにできるか。存在しないテクニック名、不正な `status`、ファイル名とフォルダのチャプター番号の不一致、テクニック名の重複、frontmatter の項目名の打ち間違い、YAML の書式エラー、存在しない文法チャプターの指定 |
| `TestDict` | テンプレート用の補助関数の引数チェック |

### 結合テスト（[builder/build_test.go](builder/build_test.go)）

| テスト | 確認していること |
| --- | --- |
| `TestBuildFixture` | テスト用コンテンツからサイトを生成し、全ページが出力されるか、ステージ・テクニックのページに解答コード・関連リンク・前後リンク・記録が出ているか |
| `TestBuildRemovesStaleFiles` | 再生成時に前回の出力が残らないか |
| `TestBuildContent` | **実際の `content/` からサイトを生成できるか**。記事の書き間違いはここで検出される |

結合テストでは、生成した全ページについて次も検査します。

- 内部リンク（`href` / `src`）の参照先ファイルがすべて存在するか（リンク切れ）
- `#アンカー` 付きリンクの参照先に、その `id` があるか
- サイトの外を指す相対リンクがないか
- テンプレートの不具合で出る文字列（`ZgotmplZ`、`<no value>`）が含まれていないか

### CI（[.github/workflows/ci.yml](.github/workflows/ci.yml)）

`main` への push とプルリクエストで実行されます。

| ジョブ | 内容 |
| --- | --- |
| 静的チェック | `gofmt`（整形）、`go mod tidy`（依存の整理漏れ）、`go vet`、`staticcheck` |
| テスト | ユニットテストと結合テスト（`-race` 付き） |
| 脆弱性チェック | `govulncheck` で依存ライブラリの既知の脆弱性を検査 |

公開用のワークフロー（[.github/workflows/pages.yml](.github/workflows/pages.yml)）でもテストを先に実行し、失敗した場合は公開しません。

## リポジトリ構成

```text
content/                     # 記事（ステージ・テクニック・文法）
builder/                     # Go 製のサイト生成ツールとテスト
docs/                        # 記事の追加手順と雛形
.claude/skills/              # Claude Code 用の記事追加スキル
.github/                     # CI・公開・Dependabot の設定
```

## このリポジトリを使って自分の解答集を作る場合

`template` ブランチを使ってください。サンプル記事だけが入った状態の仕組み一式です。

初回のみ、リポジトリの Settings → Pages → Source を「GitHub Actions」にすると、`main` への push でサイトが公開されます。
