# A=B解答集への記事追加

書式の正本は [docs/writing.md](../../../docs/writing.md)、雛形は `docs/templates/` にある。最初に docs/writing.md を読み、そのルールに従う。

## 手順

1. **種類と対象を確定する**
   - ステージ / テクニック / 文法 / チャプター概要のどれか、どのチャプター・ステージか。
   - 既存ファイルがあるか `content/` を確認する。あれば新規作成ではなく更新する。

2. **ユーザーの情報だけで書く**
   - 解答コード、行数、ステップ数、問題文、考え方はユーザーから受け取ったものだけを使う。
   - ゲームの問題文・ステージ名・文法の仕様を推測で補わない。足りない情報は聞くか、本文に「（未記入）」と残す。
   - ユーザーの解答コードは一字一句そのまま載せる。改善案があれば別に提案し、勝手に書き換えない。
   - 文体は既存の記事に合わせる（です・ます調ではなく、だ・である調の短いメモ）。

3. **ファイルを作る**
   - `docs/templates/` の雛形をもとに、docs/writing.md の置き場所・命名規則で作る。
   - ステージの `techniques` には `content/techniques/` に**実在する**ファイル名だけを書く。
     使ったテクニックがまだ無い場合は、テクニック記事も作るかユーザーに確認する。
   - 新しいチャプターのステージを追加し、そのチャプターの `_chapter.md` や文法ファイルが無い場合は、作るかどうかを聞く（無くてもビルドは通る）。

4. **確認する**
   - `go test ./...` を実行し、通ることを確認する。失敗したらエラーのファイル名を見て直す。
   - 表示確認が必要なら `go run ./builder -serve` を案内する（サーバーは起動したままにしない）。

5. **報告する**
   - 作成・更新したファイルと、自動でリンクされる先（どのテクニック・文法ページに載るか）を伝える。
   - コミット・push はユーザーに頼まれたときだけ行う。
